## Запуск

```powershell
cd "E:\_main\проект хабаровский край туризм\turism_hab_v3"
.\scripts\install-ollama.ps1     # один раз: Ollama в .runtime\ollama + модель qwen2.5:1.5b-instruct
.\start-v3.ps1 -WithExpo         # Ollama, API :8100, Streamlit :8601, Expo Web :8082
.\stop-v3.ps1                    # останавливает только порты v3
```

Без установленной Ollama всё работает: гид отвечает детерминированно из базы знаний.
Базовый режим модели — CPU (`CUDA_VISIBLE_DEVICES=-1`). GPU включается переменной
`KHAB_OLLAMA_GPU=1` только после обновления драйвера NVIDIA (сейчас 522.06).

Android Emulator: `.\start-android.ps1` (AVD `Khabarovsk_Pixel_7`, API `10.0.2.2:8100`, Metro `:8082`).
Docker: `docker compose up -d` поднимает `api` на `:8100` и `streamlit` на `:8601`;
контейнеры обращаются к Ollama хоста через `host.docker.internal:11434`.

## Расширенные карточки мест

- `content/places/*.json` — 44 карточки, связанные с каталогом по `object_id`;
  `content/profiles.json` — общие профили (город, музей, храм, мемориал, природа, экспедиция, побережье, этнография)
  для экипировки, безопасности и этикета.
- Валидация: `place_content.py` (pydantic). Запрещены цены и часы работы в тексте, только https-источники,
  дата проверки не в будущем, корректные месяцы и диапазоны времени, полное соответствие каталогу.
- `review_status`: `source_checked` — ключевые факты сверены с официальными страницами habtravel.ru;
  `needs_editor_review` — общеизвестные сведения, требующие редакторской проверки перед публикацией.
- Recognition-каталог `catalog/objects.json` не менялся, поэтому FAISS не перестраивался.

API: `/api/objects` получил краткие поля (`short_description`, `best_months_label`, `visit_label`,
`difficulty_label`, `trip_profile` …), `GET /api/objects/{id}` возвращает полную карточку.

## База знаний

`knowledge.py` генерирует `runtime/knowledge/knowledge.sqlite` (FTS5, `unicode61 remove_diacritics 2`) и
`knowledge.meta.json` с версией `kbN-<hash>`, SHA-256 контента, каталога и самой базы. База пересобирается
автоматически при изменении контента/каталога и при несовпадении SHA-256 файла базы.

## Маршруты

`POST /api/plan-route` принимает старый формат (`latitude`, `longitude`, `limit`) и новые поля
`travel_mode` (`walk`|`car`), `object_ids`, `municipality`, `available_minutes`. Ответ дополнен
`summary` (время в пути, осмотр, итог и диапазоны), `leg` у каждой остановки, `warnings` и `estimation`.

Офлайн-оценка: пешком 4,5 км/ч, автомобиль в городе 25 км/ч, между населёнными пунктами 60 км/ч;
коэффициент непрямого маршрута 1,25 (город) и 1,5 (регион). Для удалённых объектов показывается диапазон
(×2) и предупреждение, что это подготовительная оценка, а не навигация. Автоподбор не смешивает
удалённые объекты с городскими прогулками.

## ИИ-гид

`POST /api/assistant/chat` — `message` (≤1000), `object_id`, `route_object_ids`, `travel_mode`,
`history` (≤8 реплик). Ответ: `answer`, `mode` (`local_llm`|`fallback`), `grounded`, `objects`, `sources`,
`warnings`, `suggested_questions`, `knowledge_base_version`, `route_summary`. `GET /api/assistant/status`.

Схема: определение мест и типа вопроса → контекст из FTS5-базы → штатный расчёт маршрута для вопросов о
времени → локальная модель получает только найденный контекст → проверки ответа → источники.

Ограничения и защита:

- 20 запросов в минуту на IP, тайм-аут Ollama 15 с, температура 0.2, до 350 токенов;
- цены, расписания и контакты не генерируются никогда (ответ со ссылкой на источник);
- вопросы безопасности и доступности — дословно из базы;
- prompt injection в сообщении или истории отключает модель/историю;
- ответ модели отклоняется и заменяется ответом из базы, если в нём есть цены/часы/телефоны, числа или
  пункты, отсутствующие в контексте, повторы, или если он расходится с итогом штатного расчёта маршрута;
- неизвестный объект — `grounded=false`, неоднозначный вопрос — уточнение со списком мест.

История диалога хранится только в приложении (localStorage/AsyncStorage), вопросы не уходят в облако.
